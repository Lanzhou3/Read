# Android App 现代化设计与 Liquid Glass 优化方案

日期：2026-10-22。源码基线：`aa8819f38`。状态：已完成首轮原生界面落地，详见[实施与验证记录](modern-liquid-glass-implementation.md)。

## 1. 结论与检查边界

建议采用「安静的阅读内容 + 悬浮玻璃导航」：以书籍封面、阅读进度和正文建立视觉重心，顶栏、底栏与临时操作层使用 Liquid Glass 风格，统一字体、间距、图标和状态反馈。

范围为 `app/` 原生 Android 界面；`modules/web/` 的 Vue 页面作为后续独立适配范围。当前使用 XML、AppCompat、ViewBinding 与自定义 View，`minSdk 21`、`targetSdk 36`。优先沿用现有界面架构。

方案制定阶段检查了主导航、两种书架布局、书籍条目、发现、订阅、我的、搜索、书籍详情、阅读菜单和主题基础设施。当时 `adb devices -l` 返回空列表，没有运行的设备或现成 APK；以下问题表依据源码，未使用 README 历史截图作为当前证据。后续已启动 `Medium_Phone` 模拟器、构建原始和改造 APK，并完成首批实际截图；当前验证结果与剩余边界见[实施记录](modern-liquid-glass-implementation.md)。

## 3. 官方参考与设计取舍

Apple 的 iOS 27 用户指南明确增加 Liquid Glass 外观滑杆，可在通透与染色效果之间调整。本项目据此提供可调的「玻璃强度」，具体默认值由真机对比决定。[iOS 27 官方说明](https://support.apple.com/guide/iphone/whats-new-in-ios-27-iphfed2c4091/27/ios/27)

Apple HIG 将 Liquid Glass 定位为悬浮于内容之上的导航、控制层，并建议内容区域采用标准材质。本项目据此将玻璃集中在顶栏、底栏和阅读操作面板，书籍列表与正文使用稳定底色。[Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

顶栏按操作关系分组，并利用滚动边缘过渡保证辨识度；这与 Apple 对导航、工具栏和内容层次的指导一致。[Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

以下配色、尺寸、动画时长和性能门槛均为**本项目的初始设计建议**，并非 Apple 的官方参数，也不是已验证结果。

## 5. 顶栏与底栏的具体设计

### 5.1 顶栏

- 主页面：内容区展示大标题；悬浮顶栏提供搜索、添加、更多等高频操作。滚动时大标题过渡为紧凑标题，避免同时展示重复标题。
- 二级页面：返回与标题构成左侧区域，相关操作共享右侧玻璃胶囊；高频操作尽量控制在两个，其余进入更多菜单。
- 内容在顶栏后方滚动，顶部采用柔和的 scroll-edge 遮罩；玻璃按钮之上的文字、图标保持锐利。
- 紧凑操作区域起点 56dp，不含状态栏；图标可见尺寸约 24dp，触控容器至少 48×48dp。
- 书架分组与筛选属于内容层，采用轻量分段控件或标签。筛选操作保持与现有分组、排序、多选逻辑一致。

### 5.2 底栏

- 保留「书架 / 发现 / 订阅 / 我的」及用户隐藏入口的能力，采用带文字标签的悬浮圆角胶囊。
- 初始尺寸：视觉高度约 64dp，左右间距 16dp，底部距离系统安全区约 12dp；最终尺寸需在窄屏及字体放大时调整。
- 选中项使用有色图标、文字和柔和活动底板，不能仅靠颜色区分；未读角标保持独立语义和播报。
- 第一版保持底栏稳定可见。后续再验证滚动收起，优先保证入口可发现和单手操作。
- 保留底栏重复点击、页面滑动同步、隐藏入口后的定位及角标更新行为，按菜单 ID 管理状态。
- 页面底部内容 padding = 底栏实测高度 + 悬浮间距 + 系统安全区 + 内容呼吸空间；使用 `clipToPadding=false` 允许滚动经过玻璃后方，保证最后一条内容可完整移至可操作区域。
- 搜索键盘弹出时按页面场景隐藏或避让底栏；三键导航、手势导航、横屏、分屏分别验证。

### 5.3 玻璃材质与交互

材质由真实背景取样、模糊、适量染色、边缘亮暗变化、浅阴影，以及交互时的形变共同构成。仅叠加透明白色无法表达内容变化；单一背景模糊也不等于完整 Liquid Glass。

默认使用偏染色、重可读性的玻璃。可提供连续强度滑杆，并映射到染色、模糊、边缘效果的组合；另设关闭效果的清晰模式。数值变化应节流，避免快速拖动产生大量重建。

按压反馈起点为约 0.98 缩放，选择过渡约 180–240ms；边缘折射只作用于背景，不扭曲标签。遵循系统动画缩放和减少动态效果偏好，零动画模式立即切换状态。文字密集区域减少折射幅度与色散。

## 7. Android 实现路线与组件选择

### 7.1 推荐：原生 Views 渐进升级

新增共享的玻璃表面、材质策略和 inset 协议，优先在首页验证；不为外观升级立即迁移整套页面到 Compose，也不同时升级全局 AppCompat 主题父类。

| 方案 | 已查证能力 | 对当前项目的适配判断 |
| --- | --- | --- |
| [Dimezis/BlurView](https://github.com/Dimezis/BlurView) | 支持经典 Views，`BlurTarget` 提供内容，`BlurView` 模糊背景且保持子控件清晰；API 31 前后路径不同 | 推荐用于模糊基础层。需按发布 tag 固定版本并实测；它不直接提供完整液态折射或导航组件 |
| [Kyant0/AndroidLiquidGlass / Backdrop](https://github.com/Kyant0/AndroidLiquidGlass) | Compose Multiplatform 效果库，提供按钮、滑杆、底栏示例；仓库说明其不内置高层组件 | 作为材质与动效参考。只有在明确解决现有 View 内容取样之后，才评估局部 Compose 接入；不能假设包一层 ComposeView 就会自动取得兄弟 ViewPager 的背景 |
| [Android RenderEffect](https://developer.android.com/reference/android/graphics/RenderEffect) / [AGSL](https://developer.android.com/develop/ui/views/graphics/agsl/using-agsl) | RenderEffect 从 API 31 提供；RuntimeShader 相关效果需要 API 33 | 可研究现代设备上的局部边缘折射，需自行提供正确的背景输入与坐标映射；不能把 effect 直接应用于包含图标文字的根容器 |

BlurView 的取样目标不能包含指向它自己的 BlurView；按其文档划分内容层和效果层，避免递归取样。它对 SurfaceView 类内容有限制，不能据普通列表的结果推断所有媒体页面可用。[BlurView 使用说明](https://github.com/Dimezis/BlurView#how-to-use)

### 7.2 分层与接入方式

1. Activity 根布局负责全屏内容与全局底栏的叠放；内容背景绘制在可取样区域内，避免用户主题图片仅存在于 decor 背景导致取样缺失。
2. 页面内保留各自 TitleBar 的菜单和生命周期，使用一致的玻璃容器；对应取样区域只包含滚动内容，不包含该顶栏自身。
3. 首页底栏取样目标可覆盖页面内容及页面顶栏，但必须排除首页底栏自身；同时避免多个全屏取样目标重复处理相同内容。
4. 控制层依次绘制背景效果、染色/边缘、清晰的图标文字与命中容器。模糊、折射和投影不参与无障碍阅读顺序。
5. MainActivity 负责全局底部安全区；页面负责自身顶栏和内容避让；阅读器单独管理沉浸式系统栏。统一 inset 来源，逐页消除重复消费。

计划新增的职责边界：

- `ui/widget/glass/GlassSurfaceView`：形状、背景效果、描边与阴影。
- `GlassEffectPolicy`：API、模式、性能档位和用户偏好决策。
- `GlassMaterialSpec`：深浅色、强度、形状和动效参数。
- `GlassInsetsDelegate`：系统栏、IME 与内容避让；与现有工具合并去重。

这些是拟议接口，尚未创建或接入。

### 7.3 光学效果的验证门槛

先做一个可滚动书架、顶栏和底栏同时工作的技术样例，验证真实取样及性能，再决定完整光学实现：

- API 31–32：硬件模糊、染色、边缘和选择动效，作为基础玻璃档。
- API 33+：在同一背景输入上研究局部 AGSL 折射；必须验证纹理获取、坐标、裁切和帧同步，不能假定 BlurView 的内部输出可直接复用。
- 不满足性能目标时保留基础档，并把折射作为可选增强；在交付说明中明确它与完整光学档的差别。
- API 21–30 默认使用稳定的高不透明材质及同一导航造型，避免默认启用代价较高的旧式实时模糊。
- 墨水屏使用实体面、明确边界、即时状态反馈；省电、设备低性能档、用户关闭效果时停用动态取样。

接口支持在运行时切换效果档位，并保留经典界面选项，方便分批发布和排查设备差异。

## 8. 可读性、兼容性与性能验收

Android 建议交互区域至少 48×48dp；本次在顶栏、底栏、章节按钮和滑杆容器中统一落实，实际命中区域与可见图形分开检查。[Android Views 无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)

项目已 target 36，Android 16 对该目标版本不再允许退出 edge-to-edge；因此安全区适配是本次结构改造的前置项。[Android 16 行为变更](https://developer.android.com/about/versions/16/behavior-changes-16)

以下为待实施的验收标准：

- 文字对比度项目目标：普通文字至少 4.5:1，大字和关键图形至少 3:1；在明亮、深色、高频封面、自定义背景及不同玻璃强度下分别测量合成结果。
- 字体缩放 100% / 130% / 200%，360dp 窄屏、平板、横屏、分屏和 RTL；控件不截断且可操作。空间不足时布局增长或调整排列。
- TalkBack 正确播报导航名称、选中状态、未读数和按钮作用；支持键盘/方向键焦点、系统返回和减少动画。
- API 21 兼容档、API 30、31/32、33+、36；至少覆盖一台低性能设备、深浅色、墨水屏模式、两种系统导航和键盘弹出状态。
- 固定设备、相同书架数据与刷新率，对改造前后执行相同滚动、切页、菜单开关脚本；记录帧时、掉帧率、内存和长时阅读耗电。模拟器结果不能替代真机结论。
- 60Hz 设备以 16.7ms 帧预算为目标；初始门槛为玻璃带来的 P95 帧时增量不超过 2ms，掉帧率增量不超过 1 个百分点；最终门槛随基线实测校准，超限优先降级。
- 效果只在可见且背景变化时更新；页面不可见、App 后台、阅读菜单关闭时停止取样，不建立持续的无条件重绘循环。
- 不使用逐帧全屏截图和 CPU 大范围模糊作为默认方案；局部取样范围、降采样与缓存策略通过 PoC 确认。

| P2：首页落地 | 语义 token、共享玻璃组件、底栏及四个主页面；兼容自定义主题、入口隐藏与墨水屏 | 各入口、角标、重复点击、滑动同步、列表末项和键盘场景通过验证 |
| P3：全流程统一 | 搜索、详情、设置、弹窗和阅读菜单；补齐加载、错误与空态 | 核心阅读流程完整，正文排版及现有设置可用 |
| P4：验收与发布准备 | 字体缩放、无障碍、设备矩阵、性能和效果开关；整理前后截图与录屏 | 达到验收目标；性能不达标设备自动或手动降级，可切回经典界面 |

实现时运行适用的 `./gradlew :app:assembleAppDebug`、`:app:lintAppDebug` 和回归测试；设备用例通过 instrumentation 或可复现手工步骤验证。纯样式调整不增加镜像实现的单元测试；新效果策略等行为逻辑按实际边界覆盖。
